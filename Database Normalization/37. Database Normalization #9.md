## 🚀 37. Database Normalization #9

### 📌 Problem

Consider the following relation and determinants. The key(s) are **bolded**.

```
R(a, b, c, d, e)
```

Which of these determinants is a **NON-CANDIDATE key**?

1. `a, c → b, d, e`
2. `a, d → b`
3. `a, c, e → b, d`

---

### 💡 Explanation

A **candidate key** is a minimal set of attributes that uniquely identifies every tuple in a relation.

Let's examine each determinant:

- **1.** `a, c → b, d, e` ✅ Since `(a, c)` determines all the remaining attributes, `(a, c)` is a **candidate key**.
- **2.** `a, d → b` ❌ `(a, d)` determines only `b` and cannot determine all attributes of the relation. Therefore, it is **not** a candidate key.
- **3.** `a, c, e → b, d` ❌ Although `(a, c, e)` can determine `b` and `d`, it is **not minimal** because `(a, c)` alone already determines `e`, `b`, and `d`. Hence, `(a, c, e)` is a **superkey**, not a candidate key.

Among the given options, the determinant that is **not a candidate key** is:

```
a, d → b
```

---

### 💻 Solution

```text
2
```
