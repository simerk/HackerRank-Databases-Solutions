## 🚀 30. Database Normalization #2 - 1NF / 2NF / 3NF

### 📌 Problem

A particular database is normalized to satisfy a particular level of normalization (either **1NF**, **2NF**, or **3NF**).

One of the tables contains, among other fields, a column for **City** and a column for **Zip Code**.

Assuming that there is a **many-to-one mapping** between the set of **Zip Code(s)** and **City**, we may conclude that the database is definitely **NOT** in **xNF** form.

What is the integer **x** (1, 2, or 3)?

---

### 💡 Explanation

Since each **Zip Code** uniquely determines a **City**, there exists the functional dependency:

```
Zip Code → City
```

If both **Zip Code** and **City** are stored in the same table, then **City** depends on **Zip Code**, which is typically a **non-key attribute**.

This creates a **transitive dependency**:

```
Primary Key → Zip Code → City
```

A relation containing transitive dependencies **violates Third Normal Form (3NF)**.

Since a table can satisfy **1NF** and **2NF** while still violating **3NF**, we can conclude that the database is definitely **not in 3NF**.

---

### 💻 Solution

```text
3
```
