## 🚀 31. Database Normalization #3

### 📌 Problem

A database used by a college’s application stores the relationship between **Students** and the **Courses** they are enrolled in.

We have information for each:

- **STUDENT** (name, date of birth, date of enrollment, student-id, etc.)
- **COURSE** (course code, instructor, etc.)

In real life:

- A student can enroll in **multiple courses**.
- A course can have **multiple students**.

What is the **minimum number of tables** required to structure this database in accordance with the rules of **Second Normal Form (2NF)**?

---

### 💡 Explanation

The relationship between **Students** and **Courses** is **many-to-many (M:N)**.

To represent a many-to-many relationship in a normalized database, we need:

1. A **STUDENT** table to store student information.
2. A **COURSE** table to store course information.
3. An **ENROLLMENT** (or junction) table to map students to the courses they have enrolled in.

The **ENROLLMENT** table typically contains:

- `student_id`
- `course_code`

This eliminates redundancy and satisfies the requirements of **2NF**.

Therefore, the minimum number of tables required is **3**.

---

### 💻 Solution

```text
3
```
