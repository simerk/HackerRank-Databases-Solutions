## 🚀 36. Database Normalization #8

### 📌 Problem

Consider the following relations and determinants for a simple movie library.

**Relations (The key is CAPITALIZED):**

```
customer(name, addr, MEMBERNO)
movie(DESCRIPTION, director, serialno)
borrow(memberno, DATE, SERIALNO)
```

Which of the following determinants is a **NON-KEY dependency**?

1. `description → director, serialno`
2. `serialno → description`
3. `serialno → director`
4. `name, addr → memberno`
5. `memberno → name, addr`
6. `serialno, date → memberno`

---

### 💡 Explanation

A **non-key dependency** is a functional dependency in which a **non-key attribute determines another non-key attribute**.

Let's examine the dependencies:

- **1.** `description → director, serialno` ✅ `DESCRIPTION` is the declared primary key of the `movie` table.
- **2.** `serialno → description` ❌ Although `serialno` is not the declared primary key, it determines a **key attribute** (`DESCRIPTION`), so this is not considered a non-key dependency in this context.
- **3.** `serialno → director` ✅ `serialno` is a **non-key attribute**, and `director` is also a **non-key attribute**. This is a **non-key dependency**, which introduces a transitive dependency and violates **3NF**.
- **4.** `name, addr → memberno` ❌ Determines the key attribute `MEMBERNO`.
- **5.** `memberno → name, addr` ✅ Primary key dependency.
- **6.** `serialno, date → memberno` ✅ Primary key dependency.

Therefore, the non-key dependency is:

```
serialno → director
```

---

### 💻 Solution

```text
3
```
