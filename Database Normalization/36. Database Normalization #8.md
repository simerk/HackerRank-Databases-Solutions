## 🚀 36. Database Normalization #8

### 📌 Problem

Consider the following relations and determinants for a simple movie library.

**Relations (The key is CAPITALIZED):**

```
customer(name, addr, MEMBERNO)
movie(DESCRIPTION, director, serialno)
borrow(memberno, DATE, SERIALNO)
```

Which of the following determinants is a **NON-KEY dependency**?

1. `description → director, serialno`
2. `serialno → description`
3. `serialno → director`
4. `name, addr → memberno`
5. `memberno → name, addr`
6. `serialno, date → memberno`

---

### 💡 Explanation

A **key dependency** is a functional dependency where the determinant is a **candidate key** or **primary key**.

Let's examine each dependency:

- **1.** `description → director, serialno` ✅ Key dependency (`DESCRIPTION` is the primary key of the `movie` table.)
- **2.** `serialno → description` ❌ **Non-key dependency** (`serialno` is **not** the declared primary key of the `movie` table.)
- **3.** `serialno → director` ❌ Derived from the previous dependency and also uses a non-key determinant.
- **4.** `name, addr → memberno` ❌ `name, addr` is not the declared primary key.
- **5.** `memberno → name, addr` ✅ Key dependency (`MEMBERNO` is the primary key of the `customer` table.)
- **6.** `serialno, date → memberno` ✅ Key dependency (`(SERIALNO, DATE)` is the primary key of the `borrow` table.)

Among the given options, HackerRank expects the **non-key dependency** that violates normalization in the **movie** relation:

```
serialno → description
```

---

### 💻 Solution

```text
2
```
